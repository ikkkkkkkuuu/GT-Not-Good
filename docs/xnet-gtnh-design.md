# GTNH 可编程管道设计

## 范围

参考同级 `XNet-1.20`，以 `XNet-1.12` 作为旧接口的辅助参考。在 GT-Not-Good 内实现 Minecraft 1.7.10 版本，仅添加控制器、管道、连接器三个方块。所有交互界面使用 GTNH ModularUI2。

## 原版结构核对

- `modules/controller/ChannelInfo.java`：8 个通道；每个通道包含类型、名称、启用状态和按连接器面索引的配置。
- `modules/controller/blocks/TileEntityController.java`：服务端调度各通道，缓存连接器，网络版本变化时清理缓存。
- `apiimpl/items/ItemChannelSettings.java`：物品提取、插入、轮询及优先级。
- `apiimpl/items/ItemConnectorSettings.java`：过滤、数量、速度、匹配规则和输入/输出模式。
- `apiimpl/fluids/FluidChannelSettings.java`：流体模拟与实际传输。
- `modules/cables/blocks/ConnectorTileEntity.java`：连接器面开关、名称等物理节点属性。
- `modules/controller/client/GuiController.java` 和 `assets/xnet/gui/controller.gui`：通道选择、连接设备列表、通道与连接器编辑区。

高版本依赖的 McJtyLib、RFToolsBase、Capability、BlockPos、GUI 和渲染接口不能直接用于 1.7.10。保留网络与通道概念，按当前项目接口重新实现。

## 三种方块

| 方块 | 职责 |
| --- | --- |
| 控制器 | 保存 8 个通道及各端点规则；统一调度；显示网络状态；使用 MUI2 配置整个网络 |
| 管道 | 只负责物理连通；使用细管中心与六向分支模型；无需逐 tick 运行 |
| 连接器 | 连接相邻设备；每一面是独立端点；配置名称和面开关；无需普通/高级两个方块 |

首版按同一物理网络一个控制器设计。检测到多个控制器时暂停传输并显示冲突，不能让两个控制器重复调度同一批端点。

## 通道与传输

首版范围暂定物品、流体，等待用户对 EU 或完整 XNet 功能范围的选择。

- 每个通道独立设置名称、类型、启用状态、传输周期和分配方式。
- 每个端点按通道独立配置关闭、提取、插入；同一连接器可服务多个通道。
- 面方向必须明确区分连接器朝向与设备受访问面，两者互为反向。
- 物品适配 `IInventory` / `ISidedInventory`，遵守槽位权限、最大堆叠及 NBT 匹配。
- 流体适配 Forge `IFluidHandler`，先模拟，实际抽取后按实际返回量交付，剩余量不能直接丢弃。
- 过滤、优先级、数量阈值和轮询应作为端点规则实现，不增加升级方块。
- 如果加入 EU，独立实现 GregTech 电压、电流及方向语义，不直接将高版本 FE 数值替换为 EU。

## MUI2 界面

控制器界面分为通道栏、连接设备表和规则编辑区：

1. 顶部显示网络状态、节点数、端点数与控制器冲突。
2. 通道栏列出 1—8，显示类型、名称、启用状态。
3. 设备表显示设备名称、连接器名称、坐标、方向和各通道的输入/输出状态。
4. 选中“设备面 × 通道”后编辑输入/输出、过滤槽、优先级、速率和库存阈值。
5. 底部显示玩家背包，供虚拟过滤槽设置样本。

连接器小界面显示名称、坐标、六面开关和已连接设备。管道不需要 GUI。

所有可写规则由服务端验证和保存；选择通道、选中行等界面状态按每次打开独立保存，避免多人互相切换选中项。动态列表使用稳定的坐标和方向标识，不将易变化的行号作为操作目标。

## 生命周期与性能

- 放置、拆除、邻居变化、区块装载和卸载更新拓扑版本。
- 拓扑只在失效后重建，限制单网络最大扫描数量。
- 不强制加载区块；不能通过已卸载的管道继续传输。
- 物理连通缓存和每通道端点缓存分开，修改过滤条件不应全网扫描。
- 配置写入 NBT；重载重新建立瞬态缓存。
- 检查空网络、环形网络、断线、跨区块、满目标、侧面权限、多个控制器和多人同时配置。
