# 遗迹探寻罗盘

普通物品，注册名 `structure_compass`，存放于 `GTNGItemList.StructureCompass`。
无序合成：原版指南针 + 空地图 + 红砖（物品）。

- 右键：打开罗盘界面。上方选择目标，中间查看状态、坐标、距离。
- 界面按钮：开始搜索、取消搜索、清除目标、传送至目标附近安全地表。
- 未搜索到目标或目标在其他维度时，传送按钮不可用。按 ESC 关闭界面。
- 潜行右键：切换 Roguelike 红砖地牢入口 / LootGames 游戏区域，同时清除旧目标。
- 搜索期间需要保持手持；换手、离线、离开维度会取消。
- 黄色指针表示种子候选区；确认后红砖房使用红色，LootGames 使用青色。
- 搜索不生成地形，也不向客户端发送世界种子。主动传送会加载目的地地形。
- 传送限制在目标所属的当前维度，玩家共享五秒冷却。没有安全落脚点时留在原地。

## 搜索与确认

优先导航到当前维度 8192 格内最近的已记录目标。没有记录时，按从近到远的区块方形环，
调用当前安装模组的种子候选判定，检查 8192 格半径内的区域。
方形环顺序不是严格的欧氏距离排序；候选区不保证是最近的实际遗迹。

Roguelike 在候选区块附近尝试地形验证，并根据配置、生物群系等选择入口样式；
因此黄色候选区可能最终没有地牢，或者生成了其他入口样式。
红砖 HOUSE 入口与 LootGames 房间生成成功时，通过条件注册的 late mixin 写入维度存档。
手持罗盘每秒尝试将候选坐标更新为附近已记录遗迹。

旧地图通过已加载区块和候选区附近的已有 Anvil 数据补识别：
LootGames 识别原始游戏核心及已开始游戏的主方块实体；
红砖房识别地表箱子里的 Greymerk《Statistics》书及同一区块红砖。
已经取走标记书、拆改房屋、变更过生成配置的旧区域可能无法识别。
保存的是历史位置，不判断是否已搜刮、已通关或后来被拆毁。

每个搜索每 tick 最多检查 2048 个种子位置或读取 8 个已存在区块，并设置约 2ms 工作预算；
最多同时四个搜索。单次文件读取不能被预算中断。搜索不会调用生成器或加载不存在的区块。
候选到达后若没有匹配遗迹，可以潜行右键切换两次以清除目标，再搜索。

## 验证

`scripts/structure-compass-qa.init.gradle` 启动隔离的客户端测试存档，检查：
种子搜索不加载目标区块、模式切换、两种真实生成钩子、候选确认、旧游戏核心识别、
存档往返、负坐标、范围限制、拒绝岩浆/窒息位置、主动传送和罗盘渲染。

```powershell
$env:JAVA_TOOL_OPTIONS = '-Djdk.net.unixdomain.tmpdir=C:/gtng-unix-socket-fallback-missing'
.\gradlew.bat -I scripts/structure-compass-qa.init.gradle runClient --console=plain
```

该 JVM 参数沿用仓库已有 Windows QA 启动脚本的本地 socket 兼容处理。
