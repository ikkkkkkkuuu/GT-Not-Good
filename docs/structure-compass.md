# 遗迹探寻罗盘

普通物品，注册名 `structure_compass`，存放于 `GTNGItemList.StructureCompass`。
无序合成：原版指南针 + 空地图 + 红砖（物品）。

- 右键打开界面，选择野生蜂巢或 LootGames 游戏区域，查看状态、坐标与距离。
- 界面按钮：开始搜索、取消搜索、清除目标、传送至目标附近安全地表。
- 潜行右键切换目标类型并清除旧目标；原来的红砖房模式已替换为野生蜂巢。
- 蜂巢支持 Forestry、Magic Bees 和 Extra Bees 的野生蜂巢方块，不包括养蜂箱。
- 手持罗盘时，蜂巢目标使用金色指针，并在世界中以金色轮廓高亮，可透过遮挡看到。
- LootGames 已确认目标使用青色指针，尚未确认的种子候选区域使用黄色。
- 搜索期间需要保持手持；换手、离线、离开维度会取消。
- 搜索不生成地形，也不向客户端发送世界种子。主动传送会加载目的地地形。
- 传送限于目标所属的当前维度，玩家共享五秒冷却。没有安全落脚点时留在原地。
- 未找到目标或目标在其他维度时，传送按钮不可用；按 ESC 关闭界面。

## 搜索与确认

蜂巢搜索优先检查当前维度 8192 格内最近的已记录位置，再按从近到远的区块方形环，
扫描已加载区块及已存在的 Anvil 区块数据。只记录实际蜂巢方块，不预测未生成区域。
方形环不是严格的欧氏距离排序，因此搜索结果不保证是最近的蜂巢。
搜索不会加载或生成新地形；未探索、未保存的区域不在蜂巢搜索范围内。

蜂巢索引在搜索核对区块时更新，优先读取尚未写入磁盘的最新区块保存数据。
支持原版与 EndlessIDs 的存档方块编号。
手持罗盘每秒核对已加载的蜂巢目标；方块被拆除后清除目标，再次搜索可寻找其他蜂巢。
旧红砖房索引及旧罗盘的红砖房目标会自动丢弃，LootGames 记录保留。

LootGames 搜索仍优先使用 8192 格内最近的已记录目标；无记录时调用已安装版本的种子候选判定。
生成成功的游戏房间通过 late mixin 写入维度存档。靠近并加载区域后，可将候选位置确认为实际游戏房间。
旧地图识别原始游戏核心及已开始游戏的主方块实体；点击搜索时会补录周围 256 格内已加载的核心。
已经记录的游戏区域可能已通关或被修改，记录不表示仍有奖励。

每个搜索每 tick 最多检查 2048 个位置或读取 8 个已有区块，并设置约 2ms 工作预算；
最多同时四个搜索。单次文件读取不能被预算中断。搜索不会调用地形生成器。
LootGames 候选附近没有实际游戏区域时，可清除目标后换个位置搜索。

## 验证

`scripts/structure-compass-qa.init.gradle` 启动隔离客户端，检查蜂巢定位、拆除后失效、重新搜索、
原版与 EndlessIDs 存档编号、负坐标、索引迁移、未加载区块搜索，以及 LootGames 候选与生成确认。
界面回归通过正常右键收包打开，覆盖游戏复制手持物品后的按钮操作、模式切换、
未记录的已加载蜂巢与游戏核心搜索、安全传送、远处未加载目标指示，并保存蜂巢世界高亮截图。
测试客户端静音、透明、鼠标穿透并隐藏任务栏图标；窗口操作仅针对本工作区明确标记的测试进程。

```powershell
$env:JAVA_TOOL_OPTIONS = '-Djdk.net.unixdomain.tmpdir=C:/gtng-unix-socket-fallback-missing'
.\gradlew.bat -I scripts/structure-compass-qa.init.gradle runClient --console=plain
```

该 JVM 参数沿用仓库已有 Windows QA 启动脚本的本地 socket 兼容处理。
结果位于 `build/structure-compass-qa/`，截图位于其 `screenshots/` 子目录。
可传入 `-PstructureCompassQaRoot=D:/CodexQA/compass`，将测试构建、运行目录和结果分别放到该目录的
`build/`、`run/`、`results/` 子目录，便于使用其他磁盘。
