# Wireless Packaged Pattern Provider：直接绑定版

## 装配线核心

- 装配线封包核心：基础封包核心＋装配线控制器，无序合成。
- 进阶装配线封包核心：基础封包核心＋进阶装配线控制器，无序合成。
- 插入对应核心，用连接器普通右键选择供应器，再 Shift 右键绑定机器控制器。
- 含流体配方使用终极编码样板，填写一份真实配方的全部物品、流体和唯一产物。重复物品会按数据配方拆分到各段。
- 机器必须成型、开启，保留对应数据棒或数据访问仓配方，并正常供电。
- 支持普通输入总线、普通流体输入舱和一个普通输出总线，不支持 ME、共享或多流体舱。首次投料要求端点为空。
  每个输入总线的单份材料不得超过一组，流体不得超过对应输入舱容量。
- 同一终极编码样板可提前备料：普通装配线最多两份未完成任务，进阶装配线最多十七份，并受真实总线和流体舱容量限制。原料直接进入真实机器，不改变机器耗时、功率或逐段耗料规则。
- 未完成任务存在时禁止切换样板，旧存档中没有样板快照的任务先正常完成再启用预投料。多份任务及样板快照会随存档保存。
- 工作时逐 tick 检查成品，每 tick 最多检查 64 份任务并轮转；取回的产物同 tick 尝试送回 AE，网络拒收时保留在供应器内。大量绑定、总线容量或机器自身状态仍可能限制连续供料。
- 链接列表 Shift＋右键可强制中断该装配线，停止机器并一次释放其全部预投料任务，连接保留。剩余材料及已完成产物留在舱内，已消耗材料不退还；另行取消 AE 订单，清理余料后手动重启机器。注魔核心仍只释放已停止的任务。
  请勿让其他自动化同时操作这些仓。中断任务保留回执，不自动退款或生成产物。

开发验证入口：`gradlew.bat -I scripts/assembly-qa.init.gradle runClient`。
检查真实 Forge 环境中的材料分配、流体匹配、核心配方、进阶装配线访问接口和物品渲染。
该检查不替代完整成型机器的耗电加工测试。

本轮接通了 1.7.10 的方块、36 个样板槽、9 个回收槽、外置核心槽、
Connector、AE 样板发布和真实 TC4 注魔流程。材质直接使用已审计的上游文件，
TC 核心沿用上游核心底图，并动态叠加已安装 TC4 的注魔矩阵物品。

## 使用

1. 制作无线封包样板供应器、物品无线连接器和神秘注魔核心（配方见下方）。
   基础封包核心用于升级制作专用核心，自身不执行注魔。
2. 放置供应器并接入有供电、有可用频道的 ME 网络，装入神秘注魔核心。
3. 搭建 TC4 注魔祭坛，用法杖激活。中央与周围基座应为空；按 TC4 规则准备源质。
4. 手持连接器，普通右键供应器选择它，再 Shift + 右键注魔矩阵建立绑定。
   空中右键清除选择。当前只支持同维度且已加载的目标。
   手持时显示供应器到已绑定机器连接面的蓝线和蓝色高亮；选中供应器后仅显示它的连接，
   供应器变为黄色。指向尚未绑定的机器时显示黄色连接预览，收起连接器即隐藏。
5. 编码加工样板：输入包含中央物品和所有周围材料，输出填写真实注魔产物。
   装入供应器，并打开左侧自动回收按钮，再从 ME 请求合成。
6. 左侧目标按钮可查看坐标；右键列表中的空闲目标断开连接。
   带 `*` 的目标有未结束的任务记录。原样式滚动条用于查看更多目标。
   右上按钮打开优先级窗口；子页面的方块页签或 Esc 返回主界面。

## 生存配方

按用户确认的前置新增四个 GTNG 配方，均可在工作台合成，不覆盖整合包原配方：

| 产物 | 原料 |
| --- | --- |
| 基础封包核心 | 四角铁锭、四边福鲁伊克斯水晶、中心工程处理器 |
| 无线封包样板供应器 | ME 接口 + 基础封包核心 + AE 无线接收器（无序） |
| 物品无线连接器 | 左下福鲁伊克斯水晶、右上 AE 无线接收器 |
| 神秘注魔封包核心 | 基础封包核心 + TC 注魔矩阵（无序） |

## 合成控制与恢复

左侧从上到下为合成锁定、终端显示、目标管理、自动回收。前两项沿用上游 AE2
图标和行为；终端显示通过 GTNH 的 ME 接口终端 API 实现，仅暴露 36 个样板槽。
核心与回收槽不会暴露给终端。左右键可正反切换锁定模式：关闭、等待下一次
红石脉冲、有信号锁定、无信号锁定、等待产物返回网络。
“等待产物”只有在产物实际进入 ME 网络后解除；ME 存储满时仍保持锁定。
主界面锁定原因可点击重置等待条件，重置不停止祭坛、不删除任务。

祭坛损坏或产物被人工拿走后，可在目标行上 Shift + 右键释放已中断的任务记录。
该操作不会移动材料或制造退款；仍在注魔、有待回收产物或区块未加载时拒绝释放。
成功后须在 AE 合成状态中手动取消原请求，再整理祭坛并重新下单。

实际执行依赖放置者在线、位于同一世界、拥有对应研究及方块操作权限。
核心提示显示祭坛状态，自动回收提示显示进行中任务数。左侧新增同风格源质模式按钮。
默认“祭坛供给”保留 TC4 周围源质罐行为；安装神秘能源后可在空闲时切换“AE 网络直供”。
直供由 Provider 从其 AE 网络的源质元件提取，无需祭坛旁的注魔供应器。
真实祭坛每请求一点源质才扣一点库存，缺源质、断电或缺频道会等待，不回退到周围罐子。
任务期间不能切换来源。来源记录随矩阵 NBT 保存，并检查 Provider 持久身份及任务归属。
右键源质模式按钮可在空闲时循环选择 1/2/4/8/16/32 倍，默认 8 倍。
倍率仅增加每次原版吸取节拍的源质数量，不加速基座物品消耗；库存不足时只扣实际可用数量。
卸载的 Provider 区块不会被强行加载。新手动注魔会清除上一任务的来源记录。
没有替代源质或虚拟注魔模式；消耗、耗时和不稳定性由真实 TC4 祭坛处理。
同一祭坛不会重复派单，有任务时核心槽锁定。回收只取本次记录的准确产物，
ME 暂时无法接收时保留在供应器的回收槽。

## 当前边界

- 支持普通单种 ItemStack 输出的注魔，不支持附魔注魔和动态 NBT 输出。
- 当前包含 Provider、TC4 和两种装配线核心，保留直接绑定；完整无线控制器、频率、
  成员/搜索/创建和跨网络连接系统不在本次范围内。目标页面复用原背景、行样式与滚动条，
  但内容为直接绑定目标，不冒充完整频率系统。
- 子页面由 ModularUI 实现，打开时隐藏主界面，返回后恢复。
- 不支持跨维度或强制加载目标区块；依赖放置者在线并有实际研究。
- 测试不是长时间压力或大型多人服认证，也不保证所有第三方保护插件提供统一权限检查。
- reference 项目不参与编译和资源打包；原材质许可与 MIT 代码许可明确分开。

## 可重复检查

`scripts/packaged-qa.init.gradle` 将测试模组仅加入开发客户端。
运行 `scripts/run-packaged-qa.ps1`，它会启动两个独立客户端进程：先新建测试世界并保存退出，
再重开它自己创建的存档。检查绑定、重复目标、配方注册、AE 样板发布、
未激活/研究不足/基座占用拒绝、真实 TC4 启动、重复派单拒绝、NBT 保存、
源质罐消耗、成品回收、任务恢复，以及三个 GUI 窗口。
测试配方消耗 8 点风源质，另有一个未完成研究的拒绝用例；不覆盖所有生产配方或不稳定性组合。
第一阶段要求 `packaged-qa-result.txt` 为 SAVED，重启阶段要求 PASS；未完成检查使任务失败。
日志分别保存为 `build/packaged-qa-before-restart.log` 与 `build/packaged-qa-after-restart.log`。
运行时使用单独的构建快照，避免其他任务同时编译时清理客户端正在读取的类。
测试模组与测试配方不进入发布 JAR。

本机 JDK 25 的 Windows selector 问题可通过单次命令环境变量
`JAVA_TOOL_OPTIONS=-Djdk.net.unixdomain.tmpdir=C:/gtng-unix-socket-fallback-missing`
绕过；该路径须保持不存在，使 JVM 使用 TCP fallback。没有修改全局 Java 设置。

`reference/UPSTREAM_PORT_NOTES.md` 和 `src/main/resources/META-INF/ae2lt-port/`。
发布时保留署名和许可证，并实际提供 LGPL 部分的对应源码。
