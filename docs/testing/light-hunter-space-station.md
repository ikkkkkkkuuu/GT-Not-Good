# 猎光号空间站移植验证

参考 GTLAdditions `34fb152886164c56a07fc9d1b10e056f0c22b7ab`。用户选择沿用主站与卫星工厂机制。

## 运行规则

- 主站 73×73×189，原始 48,567 个非空位置及空格任意方块语义保持不变。
- 卫星工厂 5×21×13，原始 795 个非空位置；主站已有其中 770 个壳体位置。
- 原 20 个安装位，控制器沿主站后方 41 到 113 格、间隔 8 格排列，两侧各 10 个，距中轴 9 格。
  卫星工厂正面朝向主站中轴，背后一格连接器与主站连接器重合。
- 主站使用不消耗的配置电路 1，每轮 800 tick，持续消耗 536,870,912 EU/t（原 UXV 电压）。
- 主站最多 1 个普通或多安能源仓，不接受激光仓。每座工厂最多 2 个普通/多安能源仓和 1 个激光仓。
  原生及本模组无线仓按其原生能源类型识别；本模组多安无线仓计作非激光能源。
- 四类卫星工厂自行供电、输入和输出。只有启动新批次时检查主站正在运行，已开始的批次继续完成。
- 同一模式的匹配配方合并处理，总能量为各原配方 EU/t×耗时×并行数之和。
  各仓电压×额定工作安数之和决定查方功率与吞吐量，最短批次默认 20 tick，可在 GUI 修改。
  沿用原版总功率规则，不额外套用本模组执行核心或参数模块。
- 未满 64 星阵时，基础 128 线程对应总并行配额 `Integer.MAX_VALUE×128`，匹配配方公平分配。
  满 64 星阵后解除该配额，实际加工仍受原料、电压、输出空间和可表示耗时限制。
- 可选装一个原线程修正仓（Ω-天球分歧引擎），只接受普通星阵且不消耗。
  每个增加 128 线程，64 个增加 8192 线程；结合基础线程为 8320，未满阵配额为 17,867,063,943,040。
  仓内星阵不计入主站安装数量；不能共享仓室，解绑后不再提供额外配额。
- 星阵潜行右键安装，最多 64 个；拆除返还普通星阵。压缩星阵保留原 1024 等效安装行为。
  压缩产出所需奥术星图不在本次移植范围，没有新增替代产出配方。
- 1.7.10 缺少的蒸发类型映射为原生无单元化学脱水。
  原版提取功能分别接入 GTNH 提取机与流体提取机两种原生模式。
  岩石粉碎使用独立实际加工配方，明确消耗水与岩浆，不直接执行原生展示用假配方。
- 维持洁净室、低重力和精密组装机等级检查；精密组装能力按原生最高 T4（specialValue≤4）适配。

## 自动化验证

单元测试使用 `gradlew.bat test --tests '*LightHunter*'`。
本工作区以独立初始化脚本隔离主/测试类输出，避免并行任务覆盖同一类目录。
定向套件共 31 项：结构 8、渲染数学/原 OBJ 几何 4、分配与能量规则 12、原生合批处理 7。

合批测试覆盖共享输入不会重复消费、超过 int 的并行与精确产出、64 星阵前后配额、
重复物料引用、重复流体输入成本和放弃/过期快照不提交。

客户端入口：

```powershell
$env:JAVA_TOOL_OPTIONS='-Djdk.net.unixdomain.tmpdir=C:/Windows/win.ini'
.\gradlew.bat --no-daemon --no-configuration-cache -I scripts/light-hunter-qa.init.gradle runClient17
```

客户端使用独立 `run/light-hunter-qa`，仅加载测试源中的 QA 模组。
启动前冻结项目运行时 JAR，避免并行构建覆盖运行中的资源；使用 scoped HideFactoryClient 保持静音、透明、穿透及任务栏隐藏。
检查完整主站与首座工厂实际成型、连接朝向、电路与原 UXV 耗电、真实车床配方合批、
主站停机边界、64 星阵上限及实体重载，并拍摄普通恒星与满阵形态。
能源回归逐一放置普通、多安、原生无线及本模组无线仓，核对主站 1 仓和工厂 2 能源＋1 激光限制。
原生 UXV 无线 256A 目录受既有兼容 mixin 影响，按多安能源仓识别；有线 256A/1024A 激光仓仍按激光识别。
结果写入 `build/light-hunter-qa/result.txt`，截图位于同目录 `screenshots/`。
