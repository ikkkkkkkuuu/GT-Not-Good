# ME 库存控制

新增 ME 阈值输出总线、ME 双阈值发信器、ME 自动请求器与 ME 自动请求终端。
背包图标与放置模型使用上游原始几何、面贴图和状态图层，兼容原生 AE 立体部件渲染与 Angelica。
自动请求器保留原始侧面、内凹前面板与工作动画；新放置方块面向玩家，已有零 metadata 方块保留南向。
设备各占一个频道，支持物品与 GTNH 原生 AE 流体。物品按个，流体按 GTNH 的 L 显示。
输入 1000 就是 1000 L（一桶）；显示、输入、按钮步进和底层原生数量之间不做桶换算。
虚拟槽不消耗样本，支持 NEI 拖入、流体容器与原生流体包；Shift 点击清空。
物品和流体数量都支持非负 long 整数；支持 AE 数学表达式。
双阈值字段随有效输入更新、回车关闭；输出总线数量页和请求器行通过回车或对应提交按钮保存。

## 阈值输出总线

安装在线缆面向目标容器的一侧。
使用上游原始 io-bus 贴图、左侧模式工具栏和右侧升级栏。
中键点击已配置样本进入原版数量子界面，设置保留量；支持加减按钮、Shift/Ctrl 堆叠步长与返回页签。

- 高于阈值：网络中超过保留量的部分才会送出，例如保留 100000 个铁锭，额外铁锭送去做奇点。
- 不高于阈值：网络库存不大于设置值时允许输出；这个模式不会自动合成，也不控制目标容器库存。
- 默认 9 个配置槽，每张容量卡增加 18 个，最多 63 个；共有 8 个升级槽。
- 支持普通、超级、超光速加速卡，原生 GTNH 速率；支持容量卡、红石卡以及顺序/轮询/随机调度。
- 遵守接触面的 Forge 物品与流体输入限制。意外拒收的资源暂存并持久化，等待退回网络。

## 双阈值发信器

配置一个物品或流体，设置下限和上限。

- 默认模式：低于下限发信，达到上限停止。
- 反向模式：达到上限发信，低于下限停止。
- 在两条边界之间保持之前的状态。下限必须不大于上限。
- 断电、缺频道、无样本或配置无效时不输出红石。
- 存档保留中间区间的状态；重新接网时根据真实库存恢复。

## 自动请求器

连接网络后可配置 5 行库存目标；每行可单独暂停。
缺少的数量按照“目标量 − 当前库存 − 在途数量”计算，再通过原生 AE 合成 CPU 下单。
“每单量”是单次请求的最大数量；默认 0 表示自动补齐缺口。
物品和流体都必须有网络可用的样板；涉及流体的处理配方使用至尊编码样板。

界面按上游逐行显示启用框、样本、目标量、每单量、提交按钮与状态条。
每行回车或点击勾号同时提交两项数量；流体字段显示 L。
通过铁砧命名方块物品可设置中文名称，放置与掉落保留名称。
状态提示显示当前库存与在途数量。暂停或拆除只停止新订单，已经提交的订单继续由 CPU 完成并回到网络。
方块掉落保留配置，不复制合成订单；重启后的在途数量从实际 CPU 重新统计。

自动请求终端安装在线缆上，以原版分组列表直接编辑同网已加载请求器。
支持按名称或资源搜索、右键清空搜索、滚轮和拖动滚动条，以及小/中/高/全高四种自适应高度。
只同步可见行，最多 64 行；跨维度设备只有已经在同一网络且加载时才可编辑，不主动加载区块。
终端检查距离、AE BUILD 权限、网络归属和原始设备身份，断开后关闭访问。

## 大规模使用的调度策略

- 发信器只监听指定资源的变化，通知合并后再更新红石，稳定后休眠。
- 无符合条件资源的阈值总线休眠，由资源变化或邻居变化唤醒；目标满时逐步退到慢速检查。
- 库存计数使用 GTNH AE2 单资源查询接口，避免每个设备反复构建整张库存表。
- 请求器共享每个网络的队列，每 tick 最多处理 8 个设备。
- 每网最多 2 个正在计算的订单，每 10 tick 最多启动 1 次计算；不足 CPU 或材料时延迟重试。
- CPU 在途统计每网最多每 20 tick 重建一次，包含正在计算的订单预留，防止同网重复下单。
- 终端仅同步可见行；目录只在设备或配置变化、搜索变化时重建，后台不扫描世界或跨维度区块。

这些限制控制新增工作量，不保证任何规模的网络都保持 20 TPS；实际成本仍取决于 AE 存储后端、CPU 数量和配方复杂度。
