# 工作蜂箱

在工作台中用一个 Forestry 蜂箱无序合成一个工作蜂箱；也可在“GT不好：方块”创造标签页或 NEI 搜索“工作蜂箱”。注册名为 `gtnotgood:working_apiary`。

工作蜂箱继承当前整合包 Forestry 4.11.38 的 `TileApiary` 和 `BlockApiculture`，直接使用原版贴图和养蜂界面。蜂框、输入输出槽、管道交互、权限、温湿度、花朵、昼夜、天气、繁殖、后代及存档格式沿用 Forestry。新增方块不会替换原版蜂箱。资源包对原版蜂箱的贴图修改也会同步体现在工作蜂箱上。

## 配置

配置文件：游戏目录下 `config/GTNOTGOOD/gtnotgood.cfg`，分类 `WorkingApiary`（Forge 保存时分类名可能转为小写）。修改后重启服务端；单人游戏重启客户端。

| 配置键 | 默认值 | 范围 | 作用 |
| --- | ---: | ---: | --- |
| `speed` | 1 | 0.05–64 | 每游戏 tick 推进的原版养蜂 tick 数；同时影响生产、繁殖、寿命消耗、蜂框磨损和蜜蜂效果 |
| `products` | 5 | 0–64 | 普通产物成功出产后的数量倍率，包含主、副物种产物；0 禁用 |
| `specialties` | 5 | 0–64 | 特产成功出产后的数量倍率；0 禁用 |
| `lifespan` | 2147436 | 0.05–100000000 | 蜂后寿命倍率，与原版蜂框和养蜂模式叠加 |
| `mutation` | 1 | 0–64 | 原版突变概率倍率，与其他修正叠加；0 禁用突变 |

例如 `speed=4`、`products=2` 会让单位时间普通产物的期望量达到原来的约 8 倍，前提是环境符合、蜂后持续工作且及时取出产物。数量倍率的小数部分按概率取整，物品 NBT 保留，堆叠按物品上限拆分。产物概率、特产条件及花朵对产物的转换仍走原版逻辑；输出空间不足时沿用原版行为，因此高倍率应配合及时抽取。

寿命通过 Forestry 原版每轮衰老概率计算，2147436 是期望寿命倍率，并非将蜜蜂物品的 `Health` 直接写成巨大数值。高速同时加快衰老判定；该倍率只在蜂后位于工作蜂箱时生效。

本项目已有 `Forestry` 分类的全局蜜蜂设置（例如始终欢欣鼓舞、后代满基因和忽略突变条件）同样影响工作蜂箱。要与未修改的 Forestry 对照，应保持双方全局设置相同，并把本表所有倍率设为 1。

## 开发验证

`gradlew.bat compileJava processResources` 检查编译和语言资源。

`gradlew.bat -I scripts/working-apiary-qa.init.gradle runClient` 在独立的 `run/working-apiary-check` 目录启动开发客户端，使用真实 Forestry 和 Mixin 测试 500 组固定随机种子、普通/特产分别增产、零产出、原版蜂箱隔离、繁殖速度、小数时钟保存恢复、寿命修正和原版 GUI/贴图。结果及截图在 `build/working-apiary-qa`。测试类不进入发布包。

来源及资源使用记录见 `reference/UPSTREAM_PORT_NOTES.md`。
