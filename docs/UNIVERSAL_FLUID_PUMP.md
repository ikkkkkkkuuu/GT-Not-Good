# 高速通用流体泵

- 等级：LV，机器 ID 28611。支持 16A LV 输入，储能保持 32768 EU。
- 合成：GT 的 LV 泵 + LV 电动泵，工作台无序合成。
- 无需采矿管。以机器为中心，扫描下方 129×129 格区域，逐层向下直到 Y=0；不会破坏固体方块。
- 范围内的流体都会被抽取，不要求彼此连通。建议把机器放在流体表面附近，以减少扫描上方空气的等待时间。
- 每 tick 最多检查 1024 个位置、抽取 64 个流体方块；每次成功抽取消耗 8 EU，满速最高 512 EU/t。
- 原版水和岩浆源方块产出 1000 mB；流动方块被清除但不产出流体。模组流体使用 Forge `IFluidBlock` 的实际可抽取量。
- 支持下界岩浆，无维度白名单；不产生无限流体。水的原版自然再生规则仍然适用。
- 内置单流体缓存 16,000,000 mB（16000 桶）。缓存不足或遇到不同流体时，停在该位置等待输出。
- 默认开启自动流体输出，最高 64000 mB/t；通过 GT 原生输出面连接储罐或流体管道，GUI 可关闭自动输出。
- 只扫描已经加载的区块，不强制加载。每轮结束后等待 5 秒再扫描，因此稍后加载的区块会在下一轮被检查。
- 遵守 Forge 方块破坏事件；禁止假玩家抽取的领地会被跳过。流体缓存和扫描进度随世界存档保存。

## 开发验证

`scripts/universal-pump-qa.init.gradle` 使用一次性测试世界验证真实水/岩浆消耗、下界、模组流体量、批次上限、范围边界、断电/满缓存/混合流体保护、领地事件、NBT 重载、高速输出及原生 GUI。

Windows 本地 Java 若出现 loopback connection 错误，可沿用项目现有 QA 脚本的 `JAVA_TOOL_OPTIONS=-Djdk.net.unixdomain.tmpdir=C:/gtng-unix-socket-fallback-missing` 设置，再运行 `gradlew.bat -I scripts/universal-pump-qa.init.gradle runClient --console=plain`。
