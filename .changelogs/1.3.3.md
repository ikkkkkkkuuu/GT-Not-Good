本版汇总 1.3.2 发布后的全部修复，适用于 GTNH 2.9.0-RC-1。

## 超级样板输入总成按当前配方池命名

- 修复总成连接 GTNL 部分多方块时仍显示“机器名 + 编号”的问题。开启 NEI → GTNotGood 的“优先使用本模组接口自动命名”后，自动名称采用主机当前配方池，与 NEI 配方类别一致，并保留电路、手动槽和虚拟模具编号。例如化工厂使用大型化学反应配方池时，显示该配方类别的本地化名称和编号，而非“化工厂 9”。具体译名沿用客户端语言资源。
- 补齐流体输入仓连接路径，同时覆盖通用添加、物品输入总线和流体输入仓三种连接路径；只在主机接受总成后记录配方池，避免被拒绝的连接影响名称。
- 读取实际已连接主机的当前配方池，修复部分机器用螺丝刀直接切换模式后仍沿用旧名称的问题，不依赖其是否调用统一的模式切换方法。
- 使用 GregTech 通用接口，兼容安装或不安装 GTNL；修复适用于走这些连接路径的多方块，不局限于化工厂。保留玩家自定义名称、现有优先开关及无法获取配方池时的机器名称回退。
- README 更新命名说明、显示版本、发布说明及游戏包、源码包下载链接至 1.3.3。

## 验证

- 完整构建、Spotless、Checkstyle 与发布基线中的 52 项单元测试通过。
- 不安装 GTNL 的隐藏 Forge 客户端通过 3 组连接路径验证；安装 GTNL 时通过 16 组验证，覆盖化工厂、大型提取机、大型酿造厂、大型分馏蒸馏厂及螺丝刀模式切换。
- 验证原生 AE 接口终端和无线二合一接口终端的新增、重命名、分组、搜索，以及优先开关、电路/手动槽/模具编号和自定义名称。
- GTNL 名称专项测试隔离了另一个 Shimmer 延迟配方导入并发异常，不代表该启动异常已修复。验证辅助代码不进入发行包。
