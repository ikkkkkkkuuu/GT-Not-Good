本版汇总 1.3.3 发布后的全部改动，适用于 GTNH 2.9.0-RC-1。

## 库存 IO 接口（ME）

- 新增完整方块和线缆贴面两种形态，采用 ME 接口模型与高级 IO 总线的紫色配色。原生 ME 接口与高级 IO 总线无序合成，两种形态可互转并保留配置。
- GT 单方块配方直接读取 AE 网络中的物品和流体，开工时仅扣除实际消耗，不提前填入输入槽或输入罐。机器本地材料优先，不足部分可由 ME 提供。
- 合并物品、流体 GUI，各有 900 个标记，支持自动标记、网络保留量与固定可用量；两栏同步滚动，右键配置数量。可用量为 0 时仍显示资源图标和数量，保留量支持 long。
- 保留原生 GT 配方、电压、超频、输出空间等检查。材料不足、固定量不足、输出堵塞或 ME 扣料失败时不会启动配方；未能退回 ME 的真实资源会持久化保留，拆装与形态转换不会丢失。
- 回收机器明确的物品输出槽和流体输出罐，已标记的产物也能持续回收。不会抽取输入槽或输入罐，抽取仍遵守连接面与覆盖板权限。
- 当前支持走 `MTEBasicMachine` 原生通用配方检查流程的 GT 单方块机器，每次使用一个相邻接口。特殊独立配方逻辑及其他模组容器尚未接入。
- 修复高级 IO 总线在 GT 流体抽取 API 校验输入罐时无法回收输出流体的问题，保留连接面与覆盖板限制。

## 大型矿石处理副产物

- 在原生筛选产物之外，补齐粉碎、热离心和离心阶段的缺失副产物，覆盖 GT++ Kashinite、Irarsite 等没有筛选配方的矿石。
- 按实际材料登记与输入当前加工阶段选择来源，保留原生数量、概率和独立重复槽位；洗净矿、热离心矿与粉末不会再次获得已完成步骤的副产物。
- 原有粉末、宝石和筛选产物优先。同一种缺失物品存在多条可选路线时，仅选择期望产量最高的一组，避免重复叠加；富矿翻倍数量、概率不变，副产物不再次套用主粉增产倍数。
- 排除水洗、化学浸洗、电解、额外物品或流体、特殊槽和多输入加工，也不额外导入石头、下界岩与末地石粉。保留原生来源配方，重复加载不重复追加。

## 源码与说明整理

- 按方块、物品、AE 部件、网络包和机器支持代码整理包结构，同步更新注册、Mixin、渲染器与验证脚本的引用。
- 保留已有物品／方块注册 ID、机器数字 ID、网络消息编号及存档 NBT 键。封包适配器 API 移至 `common.blocks.packaged.PackagedCoreRegistry.Adapter`；引用旧包名或旧枚举成员的外部扩展需要更新引用并重新编译。
- 增加项目结构检查与库存 IO 使用说明，更新矿石副产物验证说明、上游来源及资源记录。
- README 的显示版本、发布说明、游戏包和源码包下载链接更新为 1.3.4，并补充库存 IO 与矿石机械副产物说明。
